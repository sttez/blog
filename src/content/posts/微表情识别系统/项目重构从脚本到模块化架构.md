# 项目重构：从脚本到模块化架构

## 重构前的问题

原版微表情识别系统是一个典型的"学术项目风格"代码库——所有逻辑堆在几个大文件里，到处是硬编码的路径和超参数。主要问题：

1. **推理逻辑重复**：PyQt5、Gradio、Tkinter 三个界面各自实现了一套推理代码，改一个 bug 要修三处
2. **配置散落**：`image_size = 128` 写在一个文件，`batch_size = 8` 写在另一个文件
3. **模型臃肿**：68M 参数的模型在 CASME2 上严重过拟合
4. **耦合严重**：数据预处理和训练代码混在一起，没法单独测试

## 重构后的架构

```
MicroExpressionRecognizer/
├── core/               # 核心共享模块
│   ├── config.py       # 配置管理（单例）
│   ├── detector.py     # 人脸检测 + 关键点
│   └── inference.py    # 统一推理引擎
├── models/
│   └── microexpression_model.py   # 模型定义（3M 参数）
├── training/
│   ├── trainer.py      # 训练流程（支持分阶段）
│   ├── quick_test.py   # 快速验证
│   └── metrics.py      # 评估与可视化
├── interfaces/
│   ├── desktop/        # PyQt5 桌面应用
│   └── webapp/         # Gradio Web 界面
├── data/
│   └── prepare_dataset.py   # 数据预处理
├── utils/
│   └── dataset_loader.py    # PyTorch Dataset
├── config.ini          # 集中配置
└── main.py             # Tkinter 启动器
```

四个核心模块各司其职：core 负责共享基础设施，models 负责网络结构，training 负责训练流程，interfaces 负责用户交互。

## 关键改动

### 统一推理引擎

重构最核心的改动：抽出 `InferenceEngine` 类，所有界面共用：

```python
# Before: 每个界面自己写推理
# gui_main.py 里有一套，gradio_app.py 里又一套，main.py 里还有

# After: 所有界面调用同一个引擎
engine = InferenceEngine(config)
label, probs, _ = engine.predict_image(image)
```

三个方法覆盖所有场景：`predict_image`（单张图片）、`predict_frame`（实时帧）、`predict_video`（视频文件）。

### 集中配置

`config.ini` + `Config` 单例类替代了散落各处的硬编码值。改超参数只需编辑 ini 文件，不用改代码。

### 模型瘦身

GAP 替代 Flatten + FC，参数量从 68M 降到 3M。同时加了 BatchNorm 加速训练。

### 人脸检测模块化

`core/detector.py` 封装了 OpenCV cascade + dlib 的组合检测逻辑，被推理引擎和数据预处理共同调用。

## 重构过程中的取舍

**保留了三个界面**：没砍掉任何一个，因为各有用处——PyQt5 功能最全适合日常使用，Gradio 方便在线分享，Tkinter 做启动入口最轻量。

**没用设计模式**：没有引入工厂、策略、观察者等模式。Python 项目不需要过度设计，简单清晰最重要。

**配置没用 YAML/TOML**：继续用 configparser，因为配置结构很简单，不需要更复杂的格式。

## 效果对比

| 指标 | 重构前 | 重构后 |
|------|--------|--------|
| 模型参数量 | 68M | 3M |
| 推理代码重复 | 3 处 | 0 处 |
| 配置管理 | 散落各处 | 集中 config.ini |
| 目录结构 | 扁平 | 4 模块分层 |
| 新增接口成本 | 重写推理逻辑 | 调用 InferenceEngine |

## 学到的教训

**重构要一次性做完。** 不能"先改一部分试试"，半新半旧的状态比全旧还糟糕。我花了两天时间一口气把所有模块重构完，虽然中间有段时间代码跑不起来，但最终结果是干净的。

**先抽象核心再扩展接口。** 先把 InferenceEngine 和 Config 写好，再改各个界面。反过来做的话，界面和推理逻辑的耦合永远拆不开。
