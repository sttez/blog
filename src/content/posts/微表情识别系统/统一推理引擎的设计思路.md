# 统一推理引擎的设计思路

## 为什么要统一

微表情识别系统有三个用户界面：PyQt5 桌面应用、Gradio Web 界面、Tkinter 启动器。每个界面都需要做推理——加载模型、检测人脸、提取特征、前向传播、输出概率。

如果每个界面都自己实现推理逻辑，那改一个 bug 要修三处，加一个推理模式要写三遍。这是我重构时最先要解决的问题。

## InferenceEngine 类

`core/inference.py` 中的 `InferenceEngine` 类封装了所有推理逻辑：

```python
class InferenceEngine:
    def __init__(self, config=None, model_path=None):
        self.config = config or Config()
        self.device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
        self.detector = FaceDetector(config)
        self.model = self._load_model(model_path)

    def predict_image(self, image):
        """单张图片推理"""

    def predict_frame(self, frame, frame_buffer, landmark_buffer, gray_buffer):
        """实时视频帧推理"""

    def predict_video(self, video_path):
        """逐帧视频推理"""
```

三种推理模式覆盖了所有界面的需求：

- **predict_image**：上传一张图片，返回预测类别和概率。Gradio 图像识别和 PyQt5 图片模式都用这个。
- **predict_frame**：实时摄像头模式，每帧调用一次，内部维护帧缓冲区。PyQt5 摄像头模式用这个。
- **predict_video**：传入视频文件路径，逐帧处理后返回所有帧的识别结果。Gradio 和 PyQt5 的视频模式都用这个。

## 内部流程

无论哪种推理模式，核心流程是一样的：

```
图像输入 → 人脸检测 → 特征提取 → 构建序列 → 模型前向传播 → softmax → 输出
```

不同的是序列构建方式：

- **单张图片**：将单帧重复 32 次组成伪序列，光流设为全零
- **视频帧**：用 deque 缓冲最近 32 帧，实时计算帧间光流
- **视频文件**：逐帧读取视频，累积到 32 帧后开始推理

## 界面如何使用

各界面只需实例化一个 InferenceEngine，然后调用对应方法：

```python
# Gradio Web
engine = InferenceEngine(config)
label, probs, _ = engine.predict_image(bgr_image)

# PyQt5 桌面
self.engine = InferenceEngine(self.config)
label, probs, _ = self.engine.predict_frame(
    frame, self.frame_buffer, self.landmark_buffer, self.gray_buffer
)
```

界面代码只负责用户交互和结果展示，不涉及任何推理细节。

## 模型热切换

推理引擎还支持运行时切换模型，不用重启应用：

```python
def switch_model(self, model_path):
    self.model = self._load_model(model_path)
```

PyQt5 桌面应用的菜单栏里有"切换模型"选项，列出所有已训练模型（包含准确率），点击即可切换。

## 好处

统一引擎之后，改推理逻辑只需要改一个文件。如果将来要加新的推理模式（比如批量图片推理），也只需在 InferenceEngine 里加方法，所有界面自动可用。
