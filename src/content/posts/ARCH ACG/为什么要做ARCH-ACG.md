# 为什么要做 ARCH ACG

## 起因：约拍太难了

作为一个混迹漫展圈的人，找摄影师约拍一直是个痛点——QQ 群问一圈、小红书翻半天、朋友圈转发求推荐，效率极低。妆娘、毛娘、道具师也是一样，好的服务者没有稳定的作品展示和接单渠道，需求方也没有集中的发现入口。

现有平台各有短板：

| 平台 | 定位 | 短板 |
|------|------|------|
| 小红书 | 生活方式 | ACG 内容淹没在生活流中 |
| B 站 | 视频平台 | 缺乏约单交易能力 |
| 米画师 | 画师约稿 | 只覆盖插画，不覆盖 COS/摄影 |
| 闲鱼 | 二手交易 | 没有创作者体系和作品展示 |

## 想做什么

一个 **集社区 + 约单 + 漫展资讯** 于一体的 ACG 创作者平台。

核心用户画像六类：COSER、摄影师、妆娘、毛娘、服装师、道具师。平台围绕这六类服务者构建完整的约单闭环——发布需求、服务者报价、沟通确认、完成交付、双向评价。

同时加上社交属性：作品动态、关注/粉丝、评论互动，让创作者不只是"接单机器"，而是有社区归属感的圈子。

## 技术侧的动机

这个项目对我个人来说也是全栈能力的检验场：

- **前端**：React 19 + TypeScript 6 + Vite 8 + Tailwind CSS 4，想体验最新的技术组合
- **后端**：Java 21 + Spring Boot 3.2 + MyBatis Plus，传统但稳健的方案
- **实时通信**：WebSocket 做私信和通知
- **存储**：MinIO 自建对象存储
- **缓存**：Redis 做点赞、限流、热排序等

41 张表、18 个 Controller、28 个前端页面，体量不算小。后续还有支付、AI 推荐、移动端等规划。

## 小结

ARCH ACG 不是凭空造轮子，而是从真实需求出发。二次元创作者群体足够大，却没有一个专门的平台把社区和交易结合起来。这就是做这个项目的理由。
