# 前端状态管理：Zustand + React Query 双轨制

## 核心原则

项目里有一条硬性规定：

> **禁止用 useState + useEffect 获取服务端数据。**

所有从后端来的数据，必须走 React Query。所有客户端 UI 状态（比如用户是否登录、Toast 通知列表、当前选中的 Tab），走 Zustand。

这个分界线非常清晰，不用纠结"这个状态该放哪里"。

## Zustand：客户端状态

Zustand 管三样东西：

### 1. Auth Store

```ts
export const useAuthStore = create<AuthState>((set) => ({
  user: null,
  token: null,
  login: (user, token) => set({ user, token }),
  logout: () => set({ user: null, token: null }),
}));
```

用户信息和 token 存在 Zustand 中，同时同步到 localStorage 持久化。登录/登出只需调用 `login()` / `logout()`。

### 2. Toast Store

```ts
export const useToastStore = create<ToastState>((set) => ({
  toasts: [],
  addToast: (toast) => set((s) => ({
    toasts: [...s.toasts, { id: Date.now(), ...toast }]
  })),
  removeToast: (id) => set((s) => ({
    toasts: s.toasts.filter((t) => t.id !== id)
  })),
}));
```

全局 Toast 队列，任何组件都可以 `useToastStore.getState().addToast(...)` 直接调用，不需要层层传递 props。

### 3. Notification Store

未读消息数、通知列表等客户端维护的状态。

## React Query：服务端状态

所有 API 请求用 React Query 管理：

```ts
const { data, isLoading, error } = useQuery({
  queryKey: ['feeds', { page: 1 }],
  queryFn: () => feedApi.getList({ page: 1 }),
  staleTime: 5 * 60 * 1000,  // 5 分钟内不重新请求
  gcTime: 10 * 60 * 1000,     // 10 分钟无人用则回收
  retry: 1,                    // 失败重试 1 次
});
```

React Query 自动处理的事情：

- **Loading / Error 状态**：不用手写 `const [loading, setLoading] = useState(false)`
- **缓存**：相同 queryKey 的数据自动复用
- **失效**：mutation 成功后 invalidate query，列表自动刷新
- **重试**：网络抖动自动重试
- **窗口聚焦刷新**：切回浏览器自动刷新数据

## 实际效果

对比一下两种写法：

**旧写法（useState + useEffect）：**

```tsx
const [feeds, setFeeds] = useState([]);
const [loading, setLoading] = useState(true);
const [error, setError] = useState(null);

useEffect(() => {
  setLoading(true);
  feedApi.getList()
    .then(res => setFeeds(res.data.list))
    .catch(err => setError(err))
    .finally(() => setLoading(false));
}, []);
```

**新写法（React Query）：**

```tsx
const { data, isLoading, error } = useQuery({
  queryKey: ['feeds'],
  queryFn: () => feedApi.getList(),
});
```

代码量减少 60%，还自动获得了缓存、重试、失效等能力。

## 小结

Zustand + React Query 的组合让状态管理变得非常简单——客户端状态和服务器状态泾渭分明，不需要 Redux 的 action/reducer 样板代码，也不需要自己封装 loading/error 处理。最重要的是那条铁律：**不用 useState + useEffect 获取数据**。一旦执行到位，代码质量和开发效率都会显著提升。
