# 构建二次元创作者的约单系统

## 约单是什么

ARCH ACG 的核心商业功能是"约单"——需求方发布需求，服务者（COSER、摄影师、妆娘等）申请接单，双方沟通确认后完成服务。本质上是一个双边市场的撮合系统。

## 六类服务者

| 类型 | 服务内容 | Profile 特有字段 |
|------|---------|-----------------|
| COSER | 角色扮演、漫展出展 | 可出角色、身高体重 |
| 摄影师 | 漫展跟拍、棚拍 | 器材、风格、可拍场地 |
| 妆娘 | COS 妆面 | 擅长妆面类型 |
| 毛娘 | 假发定制/造型 | 接发经验、擅长发型 |
| 服装师 | COS 服装定制 | 尺码范围、制作周期 |
| 道具师 | 道具制作 | 擅长材质、制作周期 |

每类服务者有独立的 Profile 表存储差异化信息，通过 `service_providers` 表做统一管理。

## 约单流程

```
需求方发布约单 → 服务者浏览并申请（附报价+方案）
  → 需求方选择服务者 → 双方私信沟通
  → 服务交付 → 双方互评 → 约单完成
```

状态机：

```
open → in_progress → completed
open → cancelled
```

v1.0 的状态机比较简单，后续会加入"待确认"、"申诉中"、"退款中"等状态。

## 数据库设计

```
commissions（约单需求）
├── id, title, description, category
├── budget_min, budget_max（预算范围）
├── user_id（需求方）
├── status（open/in_progress/completed/cancelled）
└── deadline

commission_applications（服务者申请）
├── commission_id, provider_id
├── price（报价）
├── proposal（服务方案）
└── status（pending/accepted/rejected）
```

搜索接口支持关键词、分类、预算范围筛选：

```
GET /api/v1/commissions?keyword=蕾姆&category=cosplay&budgetMin=200&budgetMax=500
```

## 后续计划

目前约单只是信息撮合，没有交易闭环。Phase 1 要做的：

1. **担保交易**：需求方付款到平台，服务完成后放款
2. **支付宝/微信支付**：对接国内主流支付渠道
3. **退款机制**：服务未完成可申请退款
4. **双向评价**：约单完成后双方互评，建立信用体系
5. **智能匹配**：根据需求类型自动推荐合适的服务者

## 小结

约单系统的难点不在技术，在于**信任机制**。需求方怕付钱后服务不到位，服务者怕做完后对方不付款。v1.0 先解决信息撮合的问题（让需求方找到服务者），Phase 1 再解决交易信任的问题（担保交易+评价体系）。一步到位不现实，分阶段递进才是正确的做法。
