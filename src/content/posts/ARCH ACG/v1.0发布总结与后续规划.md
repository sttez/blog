# v1.0 发布总结与后续规划

## v1.0 做了什么

经过约两个月的开发，ARCH ACG v1.0 于 2026 年 5 月 1 日发布。核心成果：

### 后端（Spring Boot 3.2）

- JWT 认证体系：accessToken + refreshToken 双 token，Redis 黑名单登出
- 安全加固：环境变量管理密钥、CORS 白名单、接口限流（60 次/分钟）
- 核心业务：用户注册登录、动态 CRUD、评论、点赞、约单发布/搜索
- 实时通信：WebSocket 私信和通知推送
- 监控：Actuator 端点暴露
- 18 个 Controller、19 个 Service、24 个 Mapper

### 前端主站（React 19）

- 28 个页面，全部 React.lazy 懒加载
- Zustand + React Query 双轨状态管理
- WebSocket 客户端 + 断线重连
- Skeleton / ErrorBoundary / LazyImage / InfiniteScroll 通用组件
- PWA 支持
- Glassmorphism 暗色设计系统

### 后台管理

- 8 个管理页面：仪表盘、用户、内容审核、约单、服务、数据、系统、作品
- 路由守卫 + 完整 API Service 层

## 踩过的坑

### 1. Mock 数据太完美

Mock 数据全是理想状态，切真实接口后 null、空数组、字段缺失等问题集中爆发。后来在 Mock 阶段就刻意造边界数据。

### 2. @RequestParam vs @RequestBody

约单创建接口用 @RequestParam 接收了 10 多个参数，URL 超长。后来统一改为 @RequestBody JSON 体。

### 3. 业务逻辑在 Controller

初期图省事在 Controller 里写业务逻辑，导致单元测试困难。后来全部下沉到 Service 层，Controller 只保留参数校验。

### 4. WebSocket 断线处理

最初没有断线重连机制，用户切换网络后 WebSocket 就断了。加了指数退避重连后解决。

### 5. 跨域配置

管理面板在 5174 端口，后端在 8080，一开始没配 CORS 白名单，请求全被拦。后来用 Vite proxy 解决开发环境，生产环境配置 CORS 白名单。

## 后续规划

### Phase 1（1-2 个月）：核心闭环

- 担保交易（支付宝/微信支付对接）
- 实名认证系统
- AI 内容审核（NSFW/暴力/政治敏感）
- 双向评价体系

### Phase 2（2-3 个月）：内容生态

- 教程系统（图文教程 + 付费课程）
- 漫展日历（漫展信息聚合）
- 话题/圈子（按 IP/角色建圈）
- 创作挑战赛

### Phase 3（3-6 个月）：平台扩展

- React Native 移动端
- 直播功能
- 电商模块
- Open API

### 技术优化时间线

| 时间 | 事项 |
|------|------|
| 2026 Q3 | Elasticsearch 全文搜索、消息队列、读写分离 |
| 2026 Q4 | CI/CD 流水线、监控告警、单元测试覆盖 |
| 2027 Q1 | 微服务拆分（Spring Cloud Gateway + Nacos） |
| 2027 Q2 | SSR/SEO 优化、国际化（日语/东南亚）、移动端 |

## 小结

v1.0 是一个"能用"的版本——核心功能闭环、前后端联调通过、部署方案就绪。距离"好用"还有很长的路，支付闭环、内容审核、推荐算法是下一步的关键。单人全栈开发的教训是：**规范先行**——API 规范、编码规范、Git 规范，这些文档投入的时间在后续开发中会成倍回报。
