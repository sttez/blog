## 问题

启动后端服务器时报错：

```
Error: listen EADDRINUSE :::3000
```

端口 3000 已经被占用。但我不记得有其他服务在用这个端口——上一次关掉终端的时候服务器应该已经停止了才对。

## 排查过程

### 第一步：查谁占了端口

Windows 下查端口占用：

```bash
netstat -ano | findstr :3000
```

输出：

```
TCP    0.0.0.0:3000           0.0.0.0:0              LISTENING       12345
```

PID 是 12345。查一下是什么进程：

```bash
tasklist | findstr 12345
```

输出：

```
node.exe    12345    Console    1    45,678 K
```

果然是 Node.js 进程。应该是上次关闭终端时，服务器进程没有正常退出——Windows 的终端关闭不会自动 kill 子进程。

### 第二步：杀掉占用进程

```bash
taskkill /PID 12345 /F
```

成功后重新启动服务器，一切正常。

但这只是一次性解决，下次关终端还会遇到同样的问题。

### 第三步：根治方案

为了避免每次手动查杀，我在 `package.json` 里加了一个启动脚本，先尝试杀掉旧进程：

```json
{
  "scripts": {
    "start": "node src/index.js",
    "start:win": "for /f \"tokens=5\" %a in ('netstat -ano ^| findstr :3000') do taskkill /PID %a /F & node src/index.js",
    "start:unix": "kill $(lsof -t -i:3000) 2>/dev/null; node src/index.js"
  }
}
```

Windows 用 `start:win`，Mac/Linux 用 `start:unix`。

但这个写法在 `package.json` 里会有转义问题。更可靠的做法是写一个小脚本 `scripts/start.js`：

```javascript
const { execSync } = require('child_process');
const os = require('os');

const PORT = 3000;

try {
  if (os.platform() === 'win32') {
    // Windows
    try {
      const output = execSync(`netstat -ano | findstr :${PORT}`, { encoding: 'utf8' });
      const pid = output.trim().split(/\s+/).pop();
      if (pid) {
        console.log(`Killing existing process on port ${PORT} (PID: ${pid})`);
        execSync(`taskkill /PID ${pid} /F`);
      }
    } catch (e) {
      // 没有找到占用端口的进程，正常
    }
  } else {
    // Mac/Linux
    try {
      execSync(`kill $(lsof -t -i:${PORT}) 2>/dev/null`);
    } catch (e) {}
  }
} catch (e) {}

require('../src/index.js');
```

然后 `package.json` 里：

```json
{
  "scripts": {
    "start": "node scripts/start.js"
  }
}
```

## 额外发现：nodemon 方案

开发阶段更好的方案是用 `nodemon`，它会自动重启服务器，并且自带端口处理：

```bash
npm install -D nodemon
```

```json
{
  "scripts": {
    "dev": "nodemon src/index.js"
  }
}
```

`nodemon` 在文件变更时自动重启，重启过程中会正确处理旧进程的端口释放。开发体验好很多。

## 学到的教训

**Windows 下关闭终端不会自动 kill Node.js 子进程。**

这是 Windows 和 Mac/Linux 的行为差异。Mac/Linux 关闭终端会发 SIGHUP 信号，子进程收到后默认退出。Windows 不会。

经验法则：

- **开发阶段用 `nodemon`**，自动处理重启和端口
- **生产环境用 `pm2` 或 `forever`**，进程管理更完善
- **手动杀进程**：`netstat -ano | findstr :端口` → `taskkill /PID xxx /F`
- **Windows 和 Mac/Linux 的 shell 命令不同**，写脚本时注意跨平台处理

另外，如果项目将来部署到 Linux，这个问题就不存在了——Linux 下 `kill` 进程后端口会立即释放。但在 Windows 开发阶段，还是得手动处理。
