# 后端集成与测试数据

## 前后端联调

前端五页面开发完成后，需要和后端 API 联调。但在联调之前，数据库里没有数据——空的表让所有页面都显示空白，根本没法测试交互。

解决方案：写一个 `seed.js` 脚本，一键生成完整的测试数据。

## seed.js 设计

脚本的执行顺序遵循外键依赖：

```javascript
const pool = require('./src/index').pool;

async function seed() {
  // 1. 按依赖顺序清空
  await pool.query('SET FOREIGN_KEY_CHECKS = 0');
  const tables = ['messages', 'conversation_members', 'conversations', 'orders', 'posts', 'users'];
  for (const table of tables) {
    await pool.query(`TRUNCATE TABLE ${table}`);
  }
  await pool.query('SET FOREIGN_KEY_CHECKS = 1');

  // 2. 插入用户（5 个角色化测试账户 + 8 个普通用户）
  const userIds = [];
  const testUsers = [
    { nickname: 'xiawei', role: 'coser', avatar: '/avatars/1.jpg', bio: '资深COSER，擅长角色还原' },
    { nickname: 'photographer_li', role: 'photographer', avatar: '/avatars/2.jpg', bio: '人像摄影5年经验' },
    { nickname: 'makeup_amy', role: 'makeup', avatar: '/avatars/3.jpg', bio: '影视级妆造' },
    { nickname: 'hairstylist_pro', role: 'hairstylist', avatar: '/avatars/4.jpg', bio: '古风发型造型' },
    { nickname: 'fan_wang', role: 'fan', avatar: '/avatars/5.jpg', bio: '二次元爱好者' },
  ];

  for (const user of testUsers) {
    const [result] = await pool.query(
      'INSERT INTO users (nickname, avatar, role, bio) VALUES (?, ?, ?, ?)',
      [user.nickname, user.avatar, user.role, user.bio]
    );
    userIds.push(result.insertId);
  }

  // 3. 插入会话和消息
  // 用户 0 和 1/2/3/4 各有一个会话
  for (let i = 1; i < userIds.length; i++) {
    const [conv] = await pool.query('INSERT INTO conversations VALUES ()');
    await pool.query('INSERT INTO conversation_members VALUES (?, ?)', [conv.insertId, userIds[0]]);
    await pool.query('INSERT INTO conversation_members VALUES (?, ?)', [conv.insertId, userIds[i]]);

    // 每个会话 2-3 条消息
    const msgs = ['你好，看到你的作品了', '想约一个拍摄', '可以的，什么时间？'];
    for (const msg of msgs) {
      await pool.query(
        'INSERT INTO messages (conversation_id, sender_id, content) VALUES (?, ?, ?)',
        [conv.insertId, userIds[Math.random() > 0.5 ? 0 : i], msg]
      );
    }
  }

  // 4. 插入帖子
  // 5. 插入订单

  console.log('✓ 用户: 13个');
  console.log('✓ 会话: 4个');
  console.log('✓ 消息: 10条');
  console.log('✓ 帖子: 5条');
  console.log('✓ 订单: 6个');
}

seed().then(() => process.exit(0));
```

## 运行方式

```bash
cd server
npm run start    # 终端1：启动服务器
node seed.js     # 终端2：插入测试数据
```

seed.js 支持重复执行——每次先 TRUNCATE 再 INSERT，保证数据干净。

## 前端联调过程

拿到测试数据后，逐页面验证 API：

| 页面 | 验证的 API | 结果 |
|------|-----------|------|
| 首页 | `GET /api/posts` | 帖子列表正常显示 |
| 首页 | `POST /api/posts` | 发布功能正常 |
| 约单 | `GET /api/orders` | 订单列表正常 |
| 消息 | `GET /api/messages/conversations` | 会话列表正常 |
| 消息 | WebSocket 连接 | 实时消息正常 |
| 教程 | `GET /api/tutorials` | 教程列表正常 |

## 常见联调问题

**CORS 跨域**：小程序的请求不走浏览器，所以没有 CORS 问题。但开发时在开发者工具里调试，需要在 Express 加上 `cors` 中间件。

**端口不一致**：确保小程序端请求的 `url` 和后端监听的端口一致。开发时统一用 `localhost:3000`，上线后改成真实域名。

**数据格式**：后端返回的数据结构要和小程序 `setData` 期望的格式一致。建议先在浏览器里调一遍 API，确认返回格式没问题再对接小程序。

## 小结

seed.js 是前后端联调的桥梁。有了测试数据，五个页面的所有交互都能完整走通。关键是按外键依赖顺序插入，以及 TRUNCATE + INSERT 的幂等执行模式，让刷新数据零成本。
