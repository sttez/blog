# 任务流编辑器的推翻重来

## 第一版：手写 Canvas，翻车了

5 月 5 号晚上，我开始做任务流页面。一开始想自己用 Canvas API 画节点和连线，觉得这样"可控性更高"。

结果写了一堆代码，效果一塌糊涂——拖拽不跟手、连线位置算不准、缩放有 bug。commit `b11d98b` 的消息是：

```
fix: 恢复任务流页面到上一版本
```

是的，整个页面回滚了。熬夜写的几百行代码全部废弃。

## 冷静下来：先写文档

那天晚上我做了一个正确的决定——不急着重写，先把设计文档写清楚。

第二天（5 月 6 日）早上，我先写了两份文档：
1. **任务流页面重新设计文档**（`00874f4`）—— 定义了需求和交互规范
2. **任务流页面实现计划**（`885167d`）—— 技术方案和任务拆解

核心结论：用 **React Flow**（`@xyflow/react`），不要自己造轮子。

## React Flow 重建

React Flow 的集成比我想象的顺利。关键代码结构：

```tsx
import { ReactFlow, Background, Controls, MiniMap } from '@xyflow/react'

export default function FlowsPage() {
  return (
    <ReactFlow
      nodes={nodes}
      edges={edges}
      onNodesChange={onNodesChange}
      onEdgesChange={onEdgesChange}
      onConnect={onConnect}
      fitView
    >
      <Background />
      <Controls />
      <MiniMap />
    </ReactFlow>
  )
}
```

但光有画布还不够。我加了几个关键功能：

### 资源包（Resource Packs）

节点不是空的方块——每个节点可以关联一个"资源包"，包含标题、描述、链接等信息。这让任务流不只是流程图，而是真正的工作流。

### 编辑模式

实现了编辑/预览模式切换。编辑模式下可以拖拽节点、连线、修改内容；预览模式下只能查看。

## 连线绕行问题

React Flow 默认的连线是贝塞尔曲线，但当节点重叠时连线会穿过节点，很丑。我写了一个自定义 Edge 组件，用 `getBezierPath` 的基础上调整控制点，让连线绕开中间的节点：

```tsx
function CustomBezierEdge({ sourceX, sourceY, targetX, targetY, ...props }) {
  const offsetY = Math.abs(targetY - sourceY) * 0.5
  const [path] = getBezierPath({
    sourceX, sourceY, targetX, targetY,
    sourcePosition: Position.Bottom,
    targetPosition: Position.Top,
    curvature: 0.3,
  })
  return <BaseEdge path={path} {...props} />
}
```

这个自定义 Edge 经过两轮调整（`ea63428` 和 `ee5fa38`）才达到满意效果。

## 小结

任务流页面是整个项目里唯一推翻重来的模块。教训很明确：

1. **不要从零造轮子**——有成熟的库就用成熟的库
2. **写代码之前先写文档**——思路清晰了，实现才快
3. **承认失败，快速止损**——回滚不丢人，死扛才是浪费时间

最终的 React Flow 版本只用了几个小时就完成了，效果远超手写 Canvas 那一版。有时候，后退一步反而更快。
