## 问题

MindHub 的任务流页面用 `@xyflow/react`（React Flow 12）来展示任务步骤。每个步骤是一张卡片节点，步骤之间用边（edge）连接。

一开始一切正常，直到我加了一个"跳步"的场景——比如步骤 1 直接连到步骤 3，中间跳过了步骤 2。这时候问题来了：连线是一条直线或者简单的贝塞尔曲线，直接穿过步骤 2 的卡片。

视觉效果非常糟糕：用户根本分不清这条线到底连的是哪个节点。

## 第一次尝试：贝塞尔曲线

我心想，React Flow 的贝塞尔曲线不是会自动弯曲吗？试试看：

```tsx
<ReactFlow
  defaultEdgeOptions={{
    type: 'smoothstep', // 或者 'default'（贝塞尔）
  }}
/>
```

结果不行。`smoothstep` 是折线式的，在垂直布局下它确实会拐弯，但拐的弯不够高，依然撞上中间的卡片。普通的贝塞尔曲线更惨——它的控制点是自动算的，完全没有"绕开障碍物"的意识。

React Flow 默认不提供"避障路由"，连线不会自动绕开中间的节点。

## 解决方案

既然框架不帮我们绕，那就自己来。

### 第一步：自定义 Edge 组件

我写了一个 `RoutingEdge` 组件，核心思路是**计算控制点，让贝塞尔曲线的弧顶高于中间节点的位置**：

```tsx
const RoutingEdge = ({
  id, sourceX, sourceY, targetX, targetY, sourcePosition, targetPosition,
}: EdgeProps) => {
  // 增大垂直方向的偏移量，让曲线拱得更高
  const yOffset = Math.abs(targetY - sourceY) * 0.6;

  const edgePath = `M ${sourceX} ${sourceY} C ${sourceX} ${sourceY - yOffset}, ${targetX} ${targetY - yOffset}, ${targetX} ${targetY}`;

  return (
    <BaseEdge path={edgePath} />
  );
};
```

关键在于控制点的 Y 坐标：两个控制点都往上偏移了源点和目标点距离的 60%，这样曲线就会大幅度拱起，从上方绕过中间节点。

### 第二步：增加容器高度

原来任务流容器高度是 300px，曲线拱起来之后溢出了。把容器高度调到 500px，给连线留足弯曲的空间。

### 第三步：z-index 处理

React Flow 默认节点的 z-index 高于连线。我加了 CSS 覆盖，确保连线浮在节点上方，视觉上更清晰：

```css
.react-flow__edge {
  z-index: 1000;
}
```

### 第四步：顺便简化卡片

在调整的过程中，我发现步骤卡片上显示的"优先级"和"预计时长"信息其实没什么用，反而让卡片显得臃肿。趁这次修改一起精简了卡片内容，只保留步骤名称和状态。

## 学到的教训

**有时候解决方案需要代码和设计两手抓。**

纯靠代码硬算连线路径，是一种"暴力解法"。但如果同时调整设计——简化卡片信息、增加容器高度——代码就不用写那么复杂，整体效果也更好。

另一个体会是：React Flow 的自定义 Edge 系统非常灵活，`EdgeProps` 给你源点、目标点的坐标和锚点方向，你可以完全自由地画路径。但"自由"也意味着"责任"——框架不帮你避障，你得自己算。对于复杂场景，可以考虑引入像 `elkjs` 这样的布局引擎来做自动避障路由。
