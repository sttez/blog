# 两天完成部署上线

## 静态导出：一个关键决定

MindHub 不需要服务端渲染。所有数据通过 Supabase 客户端直接请求，AI 调用也是客户端发起。所以我选择了 Next.js 的静态导出模式：

```typescript
// next.config.ts
const nextConfig: NextConfig = {
  output: 'export',
  images: {
    unoptimized: true, // 静态导出不支持 next/image 优化
  },
}
```

静态导出的好处：部署简单，纯静态文件，任何静态托管都能跑。代价：没有 SSR、没有 API Routes、没有服务端中间件。但对 MindHub 来说完全够用。

## 环境变量的坑

静态导出后，代码都在浏览器运行。那些用 `process.env.AI_API_KEY` 的地方全部拿不到值——因为这些变量只在构建时存在。

解决方法：给所有客户端要用的环境变量加 `NEXT_PUBLIC_` 前缀：

```bash
# .env.local
NEXT_PUBLIC_SUPABASE_URL=https://xxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJxxx
NEXT_PUBLIC_AI_BASE_URL=https://api.deepseek.com
NEXT_PUBLIC_AI_API_KEY=sk-xxx
```

这个坑体现在 commit `5c6668f`："fix: AI 环境变量添加 NEXT_PUBLIC_ 前缀"。

## Cytoscape.js 的 SSR 问题

知识图谱用的 Cytoscape.js 依赖浏览器 DOM。Next.js 构建时尝试在 Node 环境里加载它，直接报错。

解决方法：动态导入 + 禁用 SSR：

```tsx
import dynamic from 'next/dynamic'

const KnowledgeGraph = dynamic(
  () => import('@/components/KnowledgeGraph'),
  { ssr: false }
)
```

这样 Cytoscape.js 只在浏览器端加载，构建时不报错了。

## Vercel 部署

配置好后，部署到 Vercel 的流程很简单：

```bash
npm install -g vercel
vercel
```

Vercel 自动识别 Next.js 项目，构建命令是 `next build`，输出目录是 `out`。在 Vercel 控制台里添加环境变量，重新部署就完成了。

## 上线后的问题

部署不是终点。上线后发现几个问题：

1. **AI API 报错没有捕获**——用户看到白屏。修复：commit `8b64cc8`，给所有 AI 调用加了 try-catch
2. **删除资源不清理关联数据**——知识图谱里出现孤立节点。修复：commit `5ad08c4`
3. **知识图谱点击节点跳转失效**——修复：commit `d95be6f`
4. **AI 返回的 Markdown 格式混乱**——修复：同一个 commit 里的摘要格式化

## 数据库的持续优化

上线后还在继续优化。把历史记录从 localStorage 迁移到 Supabase（`5ad08c4`），AI 分析结果也缓存到数据库（`70950bd`），避免重复调用 API 浪费费用。

## 小结

两天，32 个 commit，从 `create-next-app` 到 Vercel 上线。MindHub 不是一个完美的产品，但它是一个完整的产品——有设计系统、有核心功能、有后端、有部署。

回头看，几个关键决策加速了整个过程：
- **shadcn/ui** 让我不用在 UI 细节上浪费时间
- **mock 数据先行** 让前后端可以并行
- **React Flow / Cytoscape.js** 成熟库不造轮子
- **Supabase + 静态导出** 最简后端方案

如果你也在做一个 side project，我的建议是：先跑起来，再优化。两天够做出一个像样的东西了。
