# image_picker 多选踩坑记录

## 坑一：多选 API 不一致

`pickImage()` 只能选一张。多选要用 `pickMultiImage()`，但它**没有 `maxImages` 参数**。你需要自己在代码里截断：

```dart
final images = await ImagePicker().pickMultiImage();
if (images.length > template.maxImages) {
  images.removeRange(template.maxImages, images.length);
  // 提示用户："最多只能选 N 张"
}
```

这导致一个问题：用户选了 12 张图，你截断到 9 张，用户会困惑为什么少了 3 张。更好的做法是提前在 UI 上标注数量限制。

## 坑二：Android 权限

Android 13+ 需要 `READ_MEDIA_IMAGES` 权限，之前版本需要 `READ_EXTERNAL_STORAGE`。`image_picker` 会自动处理权限请求，但如果用户拒绝了，`pickMultiImage()` 会返回空列表而不是抛异常——静默失败很难排查。

解决方案是在调用前主动检查权限状态：

```dart
final status = await Permission.photos.status;
if (status.isDenied) {
  final result = await Permission.photos.request();
  if (!result.isGranted) {
    // 引导用户去设置页开启
  }
}
```

## 坑三：图片质量

`pickMultiImage()` 默认返回原始质量的图片。大图片（4000×3000+）直接加载到 CanvasComposer 会导致内存飙升。

目前的做法是在编辑页渲染时用 `cacheWidth` 控制解码尺寸：

```dart
Image.file(
  File(imagePath),
  cacheWidth: 1080, // 足够屏幕显示，节省内存
)
```

导出时再用原始图片保证质量。

## 坑四：XFile 的 Web 兼容

`XFile` 在 Web 上没有 `path` 属性，需要调用 `readAsBytes()`。在移动设备上可以用 `Image.file(XFile(path))`，但 Web 上必须用 `Image.memory(bytes)`。这就是为什么项目里封装了一个 `XFileImage` Widget 来统一处理这两种情况。
