# 跨平台图片组件适配

## 问题

`image_picker` 返回的 `XFile` 在不同平台上的用法不同：

- **移动端**：`XFile.path` 是文件系统路径，可以用 `Image.file(File(path))`
- **Web 端**：`XFile.path` 为空，需要调用 `XFile.readAsBytes()` 获取字节数据

直接写 `Image.file(File(xfile.path))` 在 Web 上会报错。

## 解决方案：XFileImage Widget

封装一个 `XFileImage` Widget，内部判断平台选择正确的加载方式：

```dart
class XFileImage extends StatelessWidget {
  final XFile file;
  final BoxFit fit;

  @override
  Widget build(BuildContext context) {
    if (kIsWeb) {
      return FutureBuilder<Uint8List>(
        future: file.readAsBytes(),
        builder: (context, snapshot) {
          if (snapshot.hasData) {
            return Image.memory(snapshot.data!, fit: fit);
          }
          return Center(child: CircularProgressIndicator());
        },
      );
    } else {
      return Image.file(File(file.path), fit: fit);
    }
  }
}
```

## 注意事项

- Web 端的 `FutureBuilder` 每次 build 都会触发 `readAsBytes()`，需要缓存结果或用 `Future` 字段避免重复读取
- 大图片在 Web 上 `readAsBytes()` 可能较慢，需要显示 loading 状态
- 如果后续支持网络图片，需要加第三个分支处理 `Image.network`

这个封装很简单，但解决了一个跨平台开发中很常见的痛点——不同平台的文件系统 API 不一致。
