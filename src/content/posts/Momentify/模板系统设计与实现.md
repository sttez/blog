# 模板系统设计与实现

## 模型定义

模板是 Momentify 的核心数据结构。一个 `TemplateModel` 包含：

- 基本信息：id、名称、分类、描述
- 布局槽位列表 `List<LayoutSlot>`：定义每张图片的位置和尺寸
- 装饰列表 `List<TemplateDecoration>`：边框、文字、撕纸遮罩等非图片元素
- 约束：最少/最多图片数量

```dart
class TemplateModel {
  final String id;
  final String name;
  final TemplateCategory category;
  final String description;
  final List<LayoutSlot> slots;
  final List<TemplateDecoration> decorations;
  final int minImages;
  final int maxImages;
}
```

## 布局槽位

每个 `LayoutSlot` 用相对坐标（0.0-1.0）定义位置，这样不同屏幕尺寸都能正确适配：

```dart
class LayoutSlot {
  final double x;      // 相对左边界
  final double y;      // 相对上边界
  final double width;  // 相对宽度
  final double height; // 相对高度
}
```

CanvasComposer 在渲染时把相对坐标乘以实际画布尺寸，得到绝对像素位置。

## 七类模板，十八套方案

| 分类 | 数量 | 特点 |
|------|------|------|
| 拼图 collage | 3 | 多图规则排列，经典朋友圈九宫格变体 |
| 装饰 decoration | 3 | 单图 + 边框、阴影、文字装饰 |
| 故事卡片 story | 2 | 宽幅卡片布局，适合风景和旅行 |
| 笔记卡片 note | 2 | 便签风格，适合生活记录 |
| 3D 爆破 3d | 3 | 需要前景标记，图片突破九宫格边界 |
| 撕纸 tear | 4 | 四个方向的撕开效果 |
| 碎裂 shatter | 3 | 玻璃碎裂、爆炸、拼图块 |

## 模板仓库

所有模板硬编码在 `TemplateRepository` 中。当前阶段用静态数据没问题，后续迁移到服务端动态加载时，只需要替换数据源，模型层不需要改。

```dart
class TemplateRepository {
  static List<TemplateModel> getAll() => [...];
  static TemplateModel getById(String id) => ...;
  static List<TemplateModel> getByCategory(TemplateCategory cat) => ...;
}
```

## 分类驱动导航

HomePage 的筛选芯片直接对应 `TemplateCategory` 枚举。选中分类后过滤模板列表，整个联动逻辑不到 20 行代码。

模板系统搭好后，后面所有页面的开发都是"填空题"——根据模板定义渲染 UI，根据约束校验用户输入。
